# סורק הקיצוניות — Nasdaq Extreme Movers Bot

בוט שסורק את כל מניות הנאסד"ק, מוצא את המניות שקרסו הכי חזק (או זינקו הכי חזק), ומעשיר כל
מניה בסקטור, יעד מחיר של אנליסטים, כותרות חדשות אחרונות, ומשפט קצר שנוצר ע"י AI שנותן
"תחושת בטן" לגבי הסיכוי להתאוששות. שני פאנלים נפרדים:

- **סריקה יומית** — מניות שזזו קיצוני *היום* (עולים/יורדים), מתעדכן פעמיים ביום.
- **מניות שבורות** — רשימת מעקב קבועה של פני-סטוקים שכבר זמן רב שווים כמעט כלום (קרסו
  משמעותית ב-12 החודשים האחרונים ונשארו שם), בלי קשר לתנועה של היום. מתעדכנת פעם ביום.

## מבנה הפרויקט

```
backend/    FastAPI + yfinance (Yahoo Finance) + SQLite + APScheduler + OpenAI
frontend/   React (Vite), פאנל מינימליסטי בעברית
```

## איך זה עובד

1. **סריקה**: `backend/app/scanner.py` שולח שאילתת screener לא-רשמית ל-Yahoo Finance
   שמסננת מניות מהנאסד"ק (כל שלוש הרמות: NMS/NGM/NCM), ומסנן וורנטים/יחידות SPAC כברירת
   מחדל. שני מצבי סריקה:
   - `scan_nasdaq` — שינוי יומי חריג (ברירת מחדל: ⩾8%) + נפח מסחר מינימלי. מציג את **כל**
     המניות שעונות על הסינון (עם pagination עד 500), לא רק חלק קטן מהן.
   - `scan_broken_stocks` — מחיר מתחת לסף (ברירת מחדל $2) וירידה של לפחות 60% ב-12
     החודשים האחרונים, ממוינות לפי שווי שוק (הכי "לא שוות כלום" קודם).
2. **העשרה**: `backend/app/enrichment.py` מושך לכל מניה סקטור/תעשייה, יעד מחיר אנליסטים,
   והכותרות חדשות האחרונות — גם דרך Yahoo Finance. הבקשות רצות במקביל (thread pool) כדי
   שרשימה גדולה לא תיקח נצח.
3. **AI**: `backend/app/ai_summary.py` שולח את כל הנתונים ל-OpenAI (ברירת מחדל: `gpt-4o-mini`)
   ומבקש משפט אחד-שניים בעברית פשוטה, בטון "חבר מסביר לחבר". אם אין מפתח API או שהקריאה
   נכשלת, יש נוסחת גיבוי פשוטה שממשיכה לעבוד בלי AI.
4. **שמירה**: כל סריקה נשמרת ב-SQLite (`backend/stockbot.db`) כך שיש היסטוריה וניתן לטעון
   את הסריקה האחרונה מיידית בלי לחכות.
5. **תזמון**: `backend/app/scheduler.py` (APScheduler) מריץ סריקת עולים+יורדים פעמיים
   ביום (ברירת מחדל 09:45 ו-16:15), וסריקת מניות שבורות פעם ביום (ברירת מחדל 08:30) —
   הכל שעון ניו יורק, ניתן לשינוי ב-`.env`.

## הרצה ראשונה

### 1. Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate          # PowerShell: venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

ערוך את `backend/.env` והכנס את מפתח ה-OpenAI שלך:

```
OPENAI_API_KEY=sk-...החלף-במפתח-האמיתי-שלך...
```

(אפשר ליצור מפתח ב-platform.openai.com/api-keys. בלי מפתח האפליקציה עדיין עובדת,
אבל תציג משפט גנרי במקום ניתוח AI אמיתי.)

הפעלה:

```bash
python run.py
```

השרת יעלה על **http://127.0.0.1:8001** (לא 8000 — הפורט הזה תפוס אצלך ע"י שירות אחר שרץ
כבר על המחשב). התיעוד האינטראקטיבי של ה-API זמין ב-http://127.0.0.1:8001/docs.

### 2. Frontend

בטרמינל נפרד:

```bash
cd frontend
npm install
npm run dev
```

Vite יפתח על http://localhost:5173 (או פורט הבא הפנוי אם 5173 תפוס — גם הוא כבר בשימוש
אצלך). פתח את הכתובת שמופיעה בטרמינל בדפדפן.

## שימוש

- **סריקה יומית / מניות שבורות** — שני טאבים נפרדים בראש המסך, כל אחד עם היסטוריה משלו.
- **נפלו קיצוני / עלו קיצוני** — (בטאב "סריקה יומית" בלבד) מחליף כיוון סריקה.
- **סקטור** — מסנן לפי תחום (טכנולוגיה, בריאות, אנרגיה וכו').
- **מחיר מקסימלי** — מסנן מיידית (בצד הלקוח) מניות מעל מחיר מסוים.
- **סרוק עכשיו** — מריץ סריקה טרייה מול Yahoo Finance עם הסינונים הנוכחיים (יכול לקחת
  דקה-שתיים לרשימה גדולה, כי לכל מניה יש קריאות רשת נפרדות לנתונים + AI, גם אם הן רצות
  במקביל).
- ליד תאריך הסריקה האחרונה מוצג כמה מניות מוצגות מתוך כמה נמצאו בסה"כ — כדי שיהיה ברור
  שהרשימה לא חתוכה בלי הסבר.
- לחיצה על כרטיס מניה פותחת פרטים: נפח, שווי שוק, טווח 52 שבועות, יעד אנליסטים מלא,
  וקישורים לכתבות החדשות.
- כפתור הירח/שמש למעלה משמאל מחליף בין מצב בהיר לכהה (נשמר בדפדפן).

הסריקה האוטומטית רצה **רק כשה-backend פועל** — אם תסגור את השרת, היא לא תרוץ. לשימוש
רציף, השאר את `python run.py` פועל ברקע (אפשר גם עם Task Scheduler של Windows בעתיד).

## פריסה לאינטרנט (כדי שאחרים יוכלו להיכנס)

הכי פשוט: **Render** ל-backend (חינם) + **Vercel** ל-frontend (חינם). שניהם נפרסים
ישירות מ-GitHub, אז השלב הראשון הוא לדחוף את הריפו:

```bash
git remote add origin https://github.com/<username>/<repo>.git
git branch -M main
git push -u origin main
```

### Backend ב-Render

1. היכנס ל-[render.com](https://render.com) → New → Web Service → חבר את ה-GitHub repo.
2. Render יזהה את `backend/render.yaml` אוטומטית (Root Directory: `backend`). אם לא, הגדר ידנית:
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
3. במשתני הסביבה (Environment) הוסף לפחות:
   - `OPENAI_API_KEY` — המפתח האמיתי שלך
   - `FRONTEND_ORIGINS` — תעדכן אחרי שתפרוס את ה-frontend (שלב הבא), למשל
     `https://your-app.vercel.app`
4. שמור את הכתובת שקיבלת, למשל `https://nasdaq-extreme-movers-backend.onrender.com`.

### Frontend ב-Vercel

1. היכנס ל-[vercel.com](https://vercel.com) → Add New → Project → אותו GitHub repo.
2. Root Directory: `frontend` (Vercel מזהה Vite אוטומטית).
3. Environment Variables: `VITE_API_BASE` = כתובת ה-backend מ-Render (בלי `/` בסוף).
4. Deploy. תקבל כתובת קבועה כמו `https://your-app.vercel.app` — זו הכתובת שתשתף עם אחרים.
5. חזור להגדרות ה-backend ב-Render ועדכן את `FRONTEND_ORIGINS` לכתובת הזו בדיוק, אחרת
   הדפדפן יחסום את הבקשות (CORS).

### חשוב: הסריקה האוטומטית בתוכנית החינמית

שרת חינמי ב-Render "נרדם" אחרי כ-15 דקות בלי תנועה, ו"מתעורר" רק כשמגיעה בקשה (לוקח
כ-30-50 שניות לתגובה הראשונה). המשמעות: אם אף אחד לא נכנס לאתר בדיוק בשעת הסריקה
המתוזמנת (09:45/16:15/08:30), השרת עלול להיות רדום והסריקה הפנימית (APScheduler) לא
תרוץ באותו יום.

הפתרון האמין ביותר: שירות cron חיצוני וחינמי (למשל [cron-job.org](https://cron-job.org))
שמבצע קריאת POST ישירות ל-endpoint של הסריקה, בשעות הרצויות (אפשר לבחור אזור זמן
America/New_York באתר) — זה גם "מעיר" את השרת וגם מפעיל את הסריקה המדויקת בלי תלות
בטיימר הפנימי:

```
POST https://<backend-url>/api/scans/run
Content-Type: application/json
Body: {"direction": "losers"}     — ב-09:45 וב-16:15
Body: {"direction": "gainers"}    — ב-09:45 וב-16:15
Body: {"direction": "broken"}     — ב-08:30
```

(שלוש-ארבע "עבודות" cron נפרדות, כל אחת עם ה-body המתאים.)

### הערה על שמירת נתונים

ב-Render החינמי הדיסק לא קבוע — היסטוריית הסריקות (`stockbot.db`) יכולה להימחק בפריסה
מחדש של השרת. זה לא קריטי כאן כי הסריקות מתעדכנות אוטומטית כמה פעמים ביום ממילא, אבל
אם חשוב לך לשמר היסטוריה לאורך זמן, שדרג ל-instance בתשלום עם דיסק קבוע, או עבור
ל-Postgres (למשל דרך Render/Supabase בחינם) ועדכן את `DATABASE_URL`.

## הגדרות ניתנות לשינוי (`backend/.env`)

| משתנה | ברירת מחדל | הסבר |
|---|---|---|
| `SCAN_MIN_ABS_PERCENT` | 8.0 | אחוז שינוי יומי מינימלי כדי להיכנס לסריקה היומית |
| `SCAN_MIN_VOLUME` | 100000 | נפח מסחר יומי מינימלי לסריקה היומית (סינון רעש) |
| `SCAN_MAX_RESULTS` | 100 | כמה מניות מועשרות (חדשות+AI) ומוצגות, אחרי שנמצאו כל ההתאמות |
| `SCAN_EXCLUDE_DERIVATIVES` | true | הסתרת וורנטים/יחידות SPAC |
| `BROKEN_MAX_PRICE` | 2.0 | סף מחיר עליון לרשימת המניות השבורות |
| `BROKEN_MIN_DRAWDOWN_PERCENT` | 60.0 | ירידה מינימלית ב-12 החודשים האחרונים |
| `SCAN_TIME_1` / `SCAN_TIME_2` | 09:45 / 16:15 | שעות הסריקה היומית (America/New_York) |
| `BROKEN_SCAN_TIME` | 08:30 | שעת עדכון רשימת המניות השבורות |
| `OPENAI_MODEL` | gpt-4o-mini | מודל OpenAI לניתוח |

## הערות חשובות

- **מקור הנתונים** הוא ה-screener הלא-רשמי של Yahoo Finance (דרך ספריית `yfinance`).
  זה חינמי ולא דורש מפתח, אבל זה API לא רשמי — יאהו יכולים לשנות אותו או לחסום גישה מוגברת
  מדי בלי התראה. אם בעתיד תרצה יציבות גבוהה יותר, אפשר לעבור ל-Finnhub/Polygon בתשלום.
- **אחוז הירידה ב-12 חודשים בפאנל "מניות שבורות" יכול להיראות קיצוני מדי (עד ל--100%~)**
  אצל מניות שעשו reverse split — השדה של יאהו לא מתוקנן לפיצולים, אז הוא משווה למחיר
  "לפני הפיצול". זו עדיין אינדיקציה טובה למניה שקרסה קשה, רק שהמספר המדויק לא מדויק
  לגמרי — בגלל זה המיון בפאנל הזה הוא לפי שווי שוק ולא לפי האחוז הזה.
- **לאפליקציה בעתיד**: ה-backend כבר בנוי כ-API נקי (FastAPI), כך שאפשר בעתיד לבנות עליו
  אפליקציית מובייל (React Native/Flutter) בלי לשנות את הלוגיקה של הסריקה.
